# Native client retry layers

2026-10-08. Static shipped Go 10.3 II ksync Java plus local upstream LiteCore tag 3.2.2; shipped Couchbase Lite BuildConfig VERSION_NAME is 3.2.2-21. The upstream tag is a version-matched reference, not proof of identical vendor native binaries. Current physical disconnect logs corroborate its exponential sequence through 128 seconds.

CouchHolder creates ReplicatorConfiguration and sets channels, continuity, direction and filters; no Onyx calls to setMaxAttempts/setMaxAttemptWaitTime were found in the inspected Onyx Java tree. LiteCore c4RemoteReplicator.hh defaults to min(2^retryCount,300) seconds. Continuous replication has UINT_MAX retry budget; one-shot defaults to nine retries. Successful connection and a new start clear the count; explicit retry(resetCount) can clear it. Transient failures schedule timed retry. Some network-dependent failures await host reachability/network notification instead. Permanent failures do not all enter this timer.

MESSAGE MessageReplicator explicitly sets continuous true. Reader BaseReplicator defaults continuous false and retryWhenError true. Its completion/error wrapper retries startReplicator(true) up to three times with a minimum three-second spacing; successful completion clears the wrapper count/timer. This is a second layer, not a replacement for LiteCore internal retries. Some subclasses disable wrapper retry (for example NoteDocShapeReplicator); do not generalize Reader settings to all sync domains.

Bundled Alibaba OSS ClientConfiguration and OSSRetryHandler default maxErrorRetry/maxRetryCount to two. No Onyx setMaxErrorRetry override was found. Handler delay is 200 milliseconds times 2^retryIndex; invocation-index details are not inferred from the handler alone. Service status >=500 retries; RequestTimeTooSkewed receives a special corrected-time retry. Ordinary other service errors do not retry. Eligible ClientException failures retry, excluding cancellation, non-timeout InterruptedIOException and IllegalArgumentException. This per-request retry budget does not establish indefinite native workflow rescheduling after exhaustion.
