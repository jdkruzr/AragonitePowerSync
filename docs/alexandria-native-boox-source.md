User direction, recorded 2026-10-06: build a deployment plan for native BOOX
Couchbase synchronization as a **notebook and reading sync source in Alexandria
Server**. Native ksync retargeting is an intended integration route. PowerSync
owns device/protocol qualification and any small device-side setup/wakeup adapter.

Alexandria Server's present `internal/source/syncmodel.go` describes `boox` as
receive-only export. A native source needs a distinct identity, provisionally
`boox_native_couchbase`, until its merge/deletion behavior is qualified. Preserve
existing export-source behavior during this addition. Reading and notebook
qualification are separate acceptance gates.

## Intended deployment shape

Native ksync talks to an Alexandria-operated Onyx-compatible account/config/OSS
surface and Couchbase Sync Gateway. Couchbase/CBL owns wire replication and
revision/checkpoint semantics. Alexandria's public library runtime owns portable
library operations; PostgreSQL owns domain metadata and S3-compatible storage
owns durable assets. A source adapter journals native revisions and asset
receipts, applies validated domain changes, and records native application
acknowledgements separately. Hosting consumes that same runtime boundary.

The design must specify which native Couchbase records remain authoritative for
round trips, how PostgreSQL projections retain native history/provenance, and how
OSS assets reference S3 storage without a second conflicting asset authority.
Wire acceptance, asset durability, complete notebook dependency closure and native
editor application remain distinct states. Reuse real Couchbase replication.

A library represents one author across multiple independently identified devices.
Device principals, channels, credentials and asset keys must be library-scoped;
a device's requested channels are not authorization grants. Account parent fields
retain their native meaning: no fake child-account relationship for restoration.

## Conflict policy decision: native compatibility with optional server history

User decision, 2026-10-07: accept native ksync/CBL conflict winners for the live
BOOX sync source. V1 does not impose an independent newest-updatedAt or delete-wins
policy, preserve both alternatives on devices, or publish automatic compensating
revisions to override native resolution. Reading evidence motivates this decision;
notebook conflict behavior still requires its own qualification.

Keep the option for later server-side history, recovery and derived suggestions.
Separate the current native winner/domain projection from retained historical
versions or observed alternate branches. Preserve source document/revision/parent
identities, library scope, asset references and observation provenance where
available. Device attribution may be unknown; distinguish directly observed
content from inferred branches and server-derived suggestions. Capture durable
copies of observed revisions/assets if recovery is intended; Couchbase revision
retention alone is not a promised archive. Retention and discard rules remain a
future product decision.

Possible later UI: present a retained alternative on the server and let the user
choose to recover, reuse or discard it. Merely retaining or analyzing an alternative
must not change the live native winner or generate device writes. If the user
explicitly chooses an action that changes live content, it becomes a new normal
native-compatible publication, with separate delivery/application receipts.

Coverage is bounded by observation: accepted server revisions can be journaled,
but some losing device branches may resolve locally or be rejected before the
server receives their body. Do not promise complete conflict recovery from a
changes feed. Broader capture remains an optional future investigation of device
journaling or supported replication observation, not a v1 prerequisite. The
first archive should state exactly what it captured rather than claim every
losing edit. This reserves future server-side Interesting(TM) behavior while
keeping native sync semantics authoritative for device convergence.
